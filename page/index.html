cwproxy

cwproxy is a compact Go reverse proxy for local or sidecar applications. It forwards traffic to a loopback upstream, emits structured logs, and publishes EMF metrics to stdout and CloudWatch Logs.

Download binaries Quick start

What you get

  • Static binaries built with CGO_ENABLED=0.
  • Platforms: Linux AMD64, Linux ARM64, Windows AMD64, Darwin AMD64, Darwin ARM64.
  • Raw binaries published directly at the site root with SHA256SUMS.

Typical use

Run `cwproxy` beside an application that already listens on loopback, or start that application through inspector mode and let `cwproxy` discover the listen port automatically.

How To Use

Quick start guide

  1. Download the matching binary for your OS and architecture. On Linux or macOS, make it executable with chmod +x ./cwproxy-*.
  2. Start your upstream app on loopback, then run `cwproxy` with the required environment variables: 
    PROXY_PORT=8081
APP_PORT=8080
APP_NAME=my-app
HEALTH_URLS=/health
./cwproxy-linux-amd64
  3. Send traffic to PROXY_PORT. cwproxy forwards requests to 127.0.0.1:APP_PORT, logs traffic to stdout, and emits EMF metrics to stdout and CloudWatch when AWS configuration is available.

Normal Mode

Proxy an existing app

APP_PORT=8080
PROXY_PORT=8081
./cwproxy-linux-amd64

Use this when your application is already running on 127.0.0.1:APP_PORT.

Inspector Mode

Start and inspect the target app

PROXY_PORT=8081
./cwproxy-linux-amd64 node ./server.js

Use this when `cwproxy` should launch the target process and auto-detect its listening port.

Verify

Checksum validation

sha256sum -c SHA256SUMS

On Windows PowerShell, use `Get-FileHash` and compare the output with `SHA256SUMS`.

Reference

Operational notes

  • AWS_REGION or runtime metadata enables CloudWatch delivery.
  • Health logs go to /app/log/{APP_NAME}/health by default.
  • Traffic paths that match HEALTH_URLS are suppressed from traffic logs.
